# Standup

## Overview

Скилл собирает коммиты за вчерашний календарный день (по локальному времени сервера)
и формирует детальный отчёт для стендапа: не просто список заголовков коммитов, а
что именно было сделано, зачем и в каких частях монорепо (`frontend` / `backend` /
`packages/database`).

Работает только в текущем git-репозитории (`todo_learn`). Разрешены только
bash-команды `git *` и `date *` — этого достаточно, дополнительные инструменты не
нужны.

## Порядок действий

### 1. Определить диапазон "вчера"

```bash
YESTERDAY=$(date -d "yesterday" +%Y-%m-%d)
SINCE="${YESTERDAY} 00:00:00"
UNTIL="${YESTERDAY} 23:59:59"
echo "$YESTERDAY"
```

### 2. Собрать коммиты за этот диапазон по всем веткам

Использовать `--all`, т.к. часть работы может лежать в ещё не смерженной
feature-ветке:

```bash
git log --all --date-order \
  --since="$SINCE" --until="$UNTIL" \
  --pretty=format:'%n=== %h | %ad | %an | %D ===%n%s%n%n%b' \
  --date=format:'%H:%M' \
  --stat
```

- `%D` покажет, если коммит — голова ветки/тега, это помогает понять, в какой
  ветке шла работа.
- `--stat` даёт список изменённых файлов — по нему видно, к какому слою
  (`frontend/entities/...`, `backend/src/...`, `packages/database/...`) относится
  изменение, даже если scope в заголовке не указан.
- Merge-коммиты **не исключать** (не использовать `--no-merges`) — если вчера был
  смёржен PR, это тоже значимое событие для стендапа ("зафичено и смержено X").

Если вывод пустой — явно сообщить, что вчера коммитов не было (по всем веткам), и
предложить проверить незакоммиченные изменения (`git status`, `git diff`) на случай,
если работа не была закоммичена.

### 3. Разобрать и сгруппировать

Для каждого коммита разобрать заголовок по конвенции Conventional Commits
(`<type>(<scope>): <описание>`, см. скилл [[commit]]) и сгруппировать отчёт по
`scope`/области (`frontend`, `backend`, `db`, без явного scope — «прочее»).
Внутри группы — по времени коммита.

Для коммитов с телом сообщения (после пустой строки после заголовка) — обязательно
использовать текст тела для детального описания, а не пересказывать одно первое
предложение из `--stat`.

Если нужно больше контекста по конкретному коммиту (например, тело показалось
неполным или scope неочевиден из `--stat`), посмотреть полный diff:

```bash
git show --patch --stat <hash>
```

### 4. Сформировать отчёт

Итоговый текст — на русском языке (по конвенции проекта), в формате:

```
## Стендап — <YESTERDAY>

### Backend
- **<scope>**: <что сделано и зачем, 1-3 предложения на основе тела коммита/диффа>
  (`<hash>`, <HH:MM>)

### Frontend
- ...

### Прочее
- ...
```

Кратко — без воды, но детально: если коммит фиксил конкретный баг, описать сам баг
и как исправлен; если это фича — что добавлено и какие файлы/модули затронуты.
Не пересказывать заголовок коммита дословно — раскрывать его.
